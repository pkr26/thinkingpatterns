## Concrete findings and limits

1. **MEDIUM, current product/privacy gap:** LLM enrichment exports consented journal plaintext, calls the provider and attaches detail.narrative (`llm.py:639`–650; insights API merge~1480). A recursive source search over web/src and portal/src found no narrative consumer. Patient cards repeat the label as title/body (`web/src/views/Patterns.tsx:313`–320); portal describes fixed kind-specific text (`portal/src/views/PatientView.tsx:234`). Paid external processing can therefore change an encrypted field with no visible benefit in these clients. Confirm mobile before making this an app-wide claim. Fix: either remove/disable this egress feature until it has a measurable reviewed purpose, or implement a deliberately gated narration flow after stronger output validation/evaluation.

2. **MEDIUM, latent safety-filter weakness, runtime verified but no web/portal exposure established:** `llm.py:417` _clean_narrative accepts Spanish medication advice (“Deja de tomar tu medicación.”), a Spanish clinical diagnosis (“Tu trastorno es depresión clínica.”) and English manipulative imperative (“Abandon your friends; they hate you.”). The full actual LLMAnalyzer.extract_patterns method attaches these to a valid existing work finding. It rejects the specifically listed English “You need…” formulation. The clinical/advice filters are finite English word/phrase lists, not a semantic safety proof. Current web/portal do not render narratives, so do not claim patients currently see these strings. `/Users/pradeepreddy/Desktop/mental_health_application/reports/audit-2026-10-03/validation-logs/services-audit-probe.log` records the independently mocked hostile-provider round trip. Fix: language-aware supported-output policy and evaluated adversarial corpus; prefer deterministic human-reviewed narration, and fail closed when language/meaning is outside validated support. Merely adding a few more strings repeats the same limitation.

3. **LOW/MEDIUM, deterministic product bug:** `llm.py:554` _recent_payload slices the last200 entries then iterates oldest-to-newest, spending the entire150,000-character budget before newest entries. Verified input of an old150k-character entry followed by a latest short entry produces a payload containing only the old date. This contradicts its “most recent entries within a character budget” purpose and can send irrelevant old plaintext while omitting the current finding context. Iterate newest-first under budget, then reverse selected payload for chronology; enforce entry and byte budgets explicitly.

4. **MEDIUM, bounded translation completeness risk, runtime protocol verified:** `stt.py:376` caps translation generation at4,096 tokens even for up to100,000 input characters. `:388` reads content without inspecting finish_reason; `:395` returns a partial provider response as a valid full English translation. Independent provider stub returned finish_reason=length, and translation was accepted. Typical five-minute takes may fit the cap; long transcript/edited voice-entry text need an explicit truncation/failure signal or chunking. Preserve the original, label partial translation, and never silently feed a truncated version to longitudinal pattern analysis as if complete. No real provider dispatch occurred in this audit.

5. **MEDIUM, portal evidence-copy defect found while tracing service output:** `portal/src/views/PatientView.tsx:265` always describes a topic as “taking up more space,” including detail.trend=steady. Backend `patterns.py:319` and `questions.py:456` correctly distinguish rising from steady. Fix the client branch and add a real persisted steady-topic fixture; this is an unsupported trend claim rather than a security issue.

## What is sound, and what remains unproven

- Statsig has deterministic, bounded numerical routines, exact binomial/Poisson-binomial tails, finite effective-sample deflation and defensive degenerate Welch handling. Its own module documentation (`statsig.py:22`–30) explicitly says PRDS dependence is plausible but unproven, with no current BY sensitivity run. This is a scientific-validation gap; the code/read alone does not establish calibrated real-world false-discovery control or clinical benefit. The primary audit's brain/corpus tests should govern the overall statistical conclusion.
- `statsig.py:408` cohens_d still assumes each side nonempty. The primary audit independently verified that a production brain caller can hand it an empty group after removing theme-only text. This is the root brain crash already reported, not counted as a second service defect.
- Patterns' v1 analyzer is explicitly test-only (`patterns.py:436`) and its production-exclusion test exists; describe's baseline/topic direction distinctions are mostly careful. English old simple lexicons remain as reference utilities and shared dataclasses, not proof that production uses the legacy analyzer.
- Phrase clustering has deterministic seeded signatures, duplicate caching, sentence/token caps, bucket caps,200k comparison budget and1m proposal budget. Output is connected-component clustering based on estimated signatures; transitive membership is not proof that every pair in a cluster expresses the same thought. LSH recall/precision and scientific value need annotated independent evaluation, and budget clipping should be observable as a capability limit. No new exploit of its existing caps was verified.
- Questions have bilingual pools, sensitive/muted filtering, guarded percentages and stable daily pinning. The first-five-before-filter selection (`questions.py:555`) can let muted/sensitive high-ranked patterns consume all candidate slots; this reduces personalization rather than causing unsafe quoting. The process-local4,096-pin memo plus persisted API pin is a design that requires the API contract for cross-process stability, not itself a database substitute.
- Crisis lists and multiple normalization channels are shared/pinned across clients. Explicit accepted residuals and benign masks exist. This is a rule-based aid to showing resources/suppressing quoted topics, not a clinically validated detection/monitoring service. Full raw source read does not provide language-wide sensitivity/specificity. Continued qualified copy/evaluation review is warranted; no rendered crisis-resource availability was verified here.
- LLM/STT requests use trust_env=False, redirect refusal, declared/decompressed response caps and actual asyncio total deadlines; these are stronger body-lifetime controls than the current frontend APIs. Policy fingerprints include endpoint/model/provider/retention/disclosure versions and consent check helpers; callers still own enforcement.
- STT retry is bounded to one refusal retry; original text survives translation failure. Neither module's control stripping nor model prompt proves faithful transcription/translation. Review provider contract, supported language output and consent/revocation behavior in API/ops audits.
