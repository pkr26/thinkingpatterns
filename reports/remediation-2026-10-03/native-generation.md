# Native local-write generation remediation

The bounded investigation confirmed a reachable old-key publication after a completed local rekey. An Entry save's fire-and-forget mood update could retain its copied old key and an asynchronous read across prepare, credential confirmation and resume. Once the temporary freeze disappeared, the callback could overwrite the migrated mood log using the retired key. A second controlled reproduction used FIFO native-storage scheduling and 200 previously admitted callbacks; queued work surviving the temporary freeze could produce the same outcome. Both scratch cases exercised shipping crypto/store modules with synthetic identities and mocked storage. They were run before this patch and passed assertions demonstrating the defect. They were not emulator or device tests. The original scratch scripts are preserved under [evidence/native-generation](evidence/native-generation/pre-fix-generation-race.test.ts); their configuration records the original local scratch/workspace paths and is historical, not the current CI command.

## Implemented ownership contract

- `localWriteGuard.ts` captures a per-account key generation, session/origin epoch and optional in-memory key fingerprint before asynchronous producer work. Freeze and erasure retire already-captured permits; verified key installation prevents a retained old-key first invocation after unfreeze. No raw key is stored in this registry.
- Registered mood, version/binding, feedback, safety plan, pending measure and journal-draft writers preserve the permit through serialized work and check it immediately before physical publication. Native writes already submitted are tracked and drained before rekey snapshots or deletion. Pending-measure, feedback and draft ACKs use the original producer permit; administrative erasure has a separate path.
- Opaque entry/audio queues require the original key-bound producer permit after verified key installation. Entry/History/Measures producer wiring is owned by the mobile agent. It captures the original owner/scope before its first lookup and passes the same key permit through backup/translation, encryption, transport, queue admission and acknowledgement.
- Local rekey request/token/phase mutations serialize complete journal read/modify/write, preserve exact retry fields and track physical chunk/index publication under the captured scope and generation. Resume checks the complete transition owner even without a journal. Cleanup drains old publication before removing checkpoints; a retired mutation cannot recreate its token checkpoint.
- API transport checks scope after base/token awaits, after response headers and after response-body parsing, before 204 return or global 401/410 effects. A retired dispatch returns typed `stale_operation`; after dispatch the error explicitly leaves the commit outcome uncertain rather than inviting an opaque-ciphertext retry under a new bearer.
- Credential/origin/cache publication shares one physical queue, with admission and post-await epoch checks. `setSession` additionally accepts a caller-liveness check; an abandoned attempt cannot finish publication. If no newer transition exists, its partial bearer is removed; a newer transition retains ownership of its own wipe. Origin switch drains tracked commits before publishing a new URL.
- Reauthentication captures the original vault references and owner before username/salt/KDF waits. A late biometric proof cannot adopt into a replacement vault. Rotation requires the verified original owner, checks every stage, accepts only its own re-login scope advance, supports its own verified biometric auth-key adoption and reports the exact successful `sessionScope`. Retired failure cleanup cannot lock the replacement vault; private derived buffers are still zeroized. A prepared checkpoint survives uncertain retirement for recovery.
- Account erasure captures its original origin/scope and tracks administrative physical cleanup. `preserveSession:true` lets the caller perform its separately fenced sign-out; default cleanup still clears its own deleted session after local work. Scope retirement retains the sealed cleanup job for a later attempt.

## Current verification

[mobile-generation-regressions-final.log](validation-logs/mobile-generation-regressions-final.log) records 358 passing tests across 18 actual test files, including 29 new local-generation cases and 8 new proof/rotation cases. They cover FIFO queued old callbacks, held read/write/delete boundaries, retained old-key first invocation, physical drain before snapshot/erasure, exact checkpoint RMW, origin/account replacement, late 401/410/204/body responses, delayed token lookup, queued credential publication, caller retirement, cache replacement, deletion continuation, biometric proof retirement and an intentional successful re-login. The suite uses real shipping cryptography with controlled native/transport seams.

[mobile-generation-types-final.log](validation-logs/mobile-generation-types-final.log) records a passing TypeScript check. The owned files pass `git diff --check`. The mobile owner is responsible for the final combined full-suite/coverage run and updated mobile report; this focused log is not a whole-application coverage claim. The independent bounded review is recorded separately in [native-write-guard-review.md](native-write-guard-review.md).

These guards operate within one JavaScript runtime. Unit tests do not establish cross-process native CAS, hardware flush durability, iOS compilation/user-presence, multi-device recovery, provider latency or a guaranteed 90+ score. Root subsequently exercised the final frozen source on the owned Android emulator: typed text and four optional details survive force-stop/unlock, acknowledged save decrypts in History, and another restart does not resurrect the draft while reloading 11/30 progress. See [the final structured runtime log](validation-logs/android-structured-draft-final.log). This core journey does not simulate every controlled race or certify physical storage durability.
