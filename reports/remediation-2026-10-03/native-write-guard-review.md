# Bounded native write-guard review

2026-10-03. Read-only review of the stable initial `mobile/src/localWriteGuard.ts`, its `localRekey.ts` and API integration, and Entry/History/Measures producer paths. Related journal/measure erasure and queue preparation code was read only to establish physical mutation ordering. The initial common/producer review was read-only. Root subsequently authorized bounded fixes in LoginScreen.tsx, UnlockScreen.tsx, recoveryFlow.ts and RecoveryScreen.tsx; those changes and checks are recorded below. No independent device-runtime claim is made.

## Concrete findings handed to the owning agents

1. **Rotation checkpoint publication after cleanup:** `localRekey.ts` initially guarded/tracked the initial prepared journal, but `storeLocalRekeyRequest`, `storeLocalRekeyTokens` and `markLocalRekeyPhase` directly called `writeJournal`. A suspended read/chunk/index publication can outlive owner/origin retirement or erasure and republish the old checkpoint/tokens after cleanup. Capture transition ownership before the first await, serialize same-scope journal read/modify/write and track the whole physical publication so erasure drains it. The ancillary owner confirmed this gap and is implementing a delayed-publication/erasure regression.
2. **Measure acknowledgement deletion escaped the drain:** `pendingMeasure.clearPendingMeasure` directly called native `removeItem`; both successful and duplicate acknowledgement branches in Measures called it without the original permit. An admitted suspended deletion can outlive the rotation snapshot and remove the migrated/current row. Pass the existing producer permit through both ACK paths, track physical removal and keep authorized account erasure separate. Both owning agents confirmed and are implementing this contract.
3. **Credential/origin transitions could interleave:** `api.setSession`, `clearSession` and `setBaseUrl` changed the process scope and awaited drains/storage without serialization or post-await ownership checks at session publication. A delayed old-origin setSession can resume after origin retirement/credential removal/new URL persistence and write its old token into current slots. Serialize the physical credential/origin transitions, reject stale publication and regress the delayed commit ordering. Request-level response guards alone do not protect these direct storage mutations.
4. **Producer permit capture followed a mutable first lookup:** Entry/Measures (History analogous) first awaited getUserId and then read the current vault/captured a permit. If the lookup spans replacement ownership and resolves with the new owner, the old screen's content can receive a new valid permit/new key. Capture scope/verified owner before the first await, recheck after lookup and require vault-owner equality. Regress a suspended first-owner lookup, in addition to existing delayed translation/backup cases. Sent to the mobile owner.

The no-journal `resumeLocalRekey` activation branch was also flagged to check full transition owner/scope before installation, rather than epoch equality alone. Installing a key is not itself cryptographic proof that it belongs to the mutable session owner.

## Bounded positive observations and limits

The initial guard retires permits on freeze and scope changes, validates installed key identity, synchronously registers admitted physical producer commits and drains them before preparation/erasure. Queue/audio preparation uses the same process mutex as its metadata mutations. Entry/History already preserve captured permits across translation/encryption/retry/send once capture occurs. API ownership checks run after token lookup, response headers and response-body parsing before authenticated 401/410 hooks, preventing a late previous-session response from locking its replacement.

These observations concern one JS runtime. They do not establish native cross-process compare-and-set, hardware flush durability, a complete competing-device recovery matrix, or race-free login/unlock UI lifecycle outside this scope. The findings above describe the initial implementation. Their final disposition and independent verification scope are recorded below.

## Final disposition of the four review findings

All four source gaps are now addressed in the owning agents' frozen source:

- Journal request/token/phase mutations capture transition scope and key generation, serialize same-scope RMW and track the complete physical checkpoint write. No-journal resume checks full transition ownership before key installation.
- Measure ACK cleanup uses the captured key-bound producer permit and tracked physical deletion; explicit `erasePendingMeasure` is reserved for authorized erasure. Both 201 and 409 screen paths pass the original permit. Equivalent feedback/safety-plan draft ACK boundaries were corrected by the common owner.
- Session installation, session removal, origin change and credential caches share serialized physical operations and captured-epoch checks. A caller `stillCurrent` proof is checked throughout setSession publication; retired partial publication is removed only when a newer epoch does not own replacement credentials.
- Entry/History/Measures capture the scope synchronously before their first owner lookup, reject a changed scope and require vault-owner equality before capturing the producer permit. The mobile owner reports actual first-lookup and deferred-producer regressions.

The final common source was independently reread at these boundaries. This agent independently ran **29/29 localWriteGeneration.test.ts cases** successfully; see [the final boundary log](validation-logs/mindpattern-mobile-write-guard-review-final.log) for its exact count. The broader **358 common/rotation** and **362 producer/Settings** passing targeted tests are owner-reported, not claimed as independently executed here. Full native coverage/red-team/device validation belongs to the mobile/root owners.

## Subsequent bounded authentication fix

Root explicitly authorized four authentication files and their focused tests. Three original regressions failed on the shipping pre-fix paths: a verifier dispatched after an origin change during KDF, a late biometric completion replaced the newly unlocked vault after unmount, and recovery reset continued after foreign scope retirement. [Retained red reproduction](validation-logs/mindpattern-mobile-auth-ownership-red.log).

Login/password unlock/biometric unlock/recovery now capture synchronous ownership before their first await, retain a component attempt/mount proof and check it before credential dispatch, private-key adoption and error cleanup. Each deliberate setSession admission captures its own new epoch synchronously and supplies the caller-liveness proof to the API's physical credential writes. Stale catches zeroize private buffers without locking or clearing a replacement vault/session. Interrupted rotation continuation uses the delegate's actual `sessionScope` completion proof rather than guessing epoch advancement.

RecoveryFlow additionally accepts the component proof and returns its exact ownershipEpoch. RecoveryScreen verifies that epoch at return-to-adoption, zeroizes an abandoned returned key, cancels its delayed navigation on unmount and checks scope before navigation. Successfully committed resets retain their existing cache-failure semantics; the guard never pretends a dispatched remote mutation was cancelled. Unwrapped data keys acquire private cleanup ownership before any subsequent storage await.

Final focused authentication suites: **7 files, 146/146 tests PASS**; [final log](validation-logs/mindpattern-mobile-auth-ownership-final3.log). TypeScript and git diff --check PASS. Two prior mock tests explicitly tolerated absent/empty owner binding and now assert refusal; one duplicate-submit fixture was corrected to return the same immutable owner while retaining all original duplicate-submit assertions. Real API setSession already rejects invalid account IDs; these tests now reflect trusted-owner custody. New delayed derivation, unmount, replacement-session and abandoned-key assertions remain strict. No coverage threshold was lowered.

Changed authentication production files: `mobile/src/screens/LoginScreen.tsx`, `mobile/src/screens/UnlockScreen.tsx`, `mobile/src/recoveryFlow.ts`, `mobile/src/screens/RecoveryScreen.tsx`. Targeted tests: new `mobile/tests/screens/authOwnership.test.tsx`, plus loginScreen/unlockScreen/recoveryScreen/recoveryFlow contract updates and regressions. Common guard/API/rotation/producer implementations remain owned by their respective agents.

Authentication and common source are frozen as of the final focused checks above. This is single-runtime source/behavioral evidence, not a claim of native hardware durability, cross-process CAS or complete competing-device recovery.
