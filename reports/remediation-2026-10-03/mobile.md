## Additional important implementation

- Legacy corpus/key/credential rotation now uses the backend's atomic UUID operation protocol. The exact verifier/body/token headers survive a lost response; no separate credential mutation or post-commit grant rewrap remains. All current grant wraps are staged before remote mutation; the backend fences grant/key additions and allows privacy revocation. Response `consents_rewrapped` reports the actual active grant count. A new-password proof alone cannot apply local replacements before online credential confirmation.
- Recorder custody is acquired as ciphertext before the parent entry's network request. Parent waiting status prevents orphan uploads; the same client entry ID heals an acknowledged parent whose response was lost. No automatic full-queue eviction or rejected-upload deletion exists.
- Self-contained saved-recording JSON includes canonical username, envelope/salt/KDF metadata, ciphertext and audio metadata. It never exports a raw data key or plaintext. Sharing retains the original queue and an encrypted scoped export file until explicit deletion/account cleanup, because native consumers can read after the share call returns.
- `engine.native.ts` statically imports the linked QuickCrypto backend. Metro cannot resolve the previous aliased dynamic require; native initialization failures no longer fall back to unavailable Node crypto. Node tools continue to run the shipping KDF/AAD/envelope modules with their Node backend.
- An acknowledged entry save now refreshes the server's authoritative distinct-day progress without incrementing it for queued entries or duplicate-day writes. Session boot and verified Unlock also fetch the authoritative count; the UI shows loading/unavailable until a real value is known and retains a same-owner known value on failed refresh. Request-order/account-generation/owner proofs captured before an Insights fetch prevent late responses from overwriting a newer count, crossing a sign-out/origin change, or applying after screen/provider unmount. Actual-provider delayed old-account/unmounted-screen regressions cover the adoption path. Mounted journal starter chips refresh with the selected language while user-authored draft text is preserved.

- Typed journal drafts now persist as authenticated encrypted owner/origin-bound records with complete mood/energy/sleep/tags. Read failures and unreadable ciphertext are retained; newer typing cannot be clobbered by hydration, and Save ACK clears only the matching editor revision after durable server/outbox save. A complete RAM fallback preserves failed-backup edits through lock; disk-first/RAM-first arrivals and late RAM versus new typing present explicit recovery choices. Drafts participate in local rekey and account erasure. Unsaved voice recordings are excluded from the typed-draft promise.
- Entry/History/Measures producers capture key-bound permits before asynchronous backup/translation and preserve the same permit through upload/queue/ACK. The session epoch is also captured before the first owner lookup, and the resolved owner must match the verified vault owner. Delayed initial-account replacement and completed-rotation regressions reject stale ciphertext without discarding on-screen text/answers.
- EN/ES Unlock privacy copy accurately distinguishes encrypted sync/metadata, explicitly requested transient analysis-key access, and optional voice/translation processing.

- Persistent lifecycle/key generations now fence registered store writes and opaque ciphertext producers through the actual native commit. A key-bound producer admitted before freeze cannot become valid after completed rekey; rotation/erasure drain admitted physical commits before snapshot/removal. Pending-measure, feedback, safety-plan and entry/audio ACK deletion retain the original producer permit. See [native-generation.md](native-generation.md), including the preserved pre-fix corruption evidence and 37 new generation/rotation regressions.
- Login, password/biometric Unlock and recovery bind the original server/account/attempt before the first await, carry liveness through physical credential adoption, and zeroize abandoned derived/restored keys. A late failed old login cannot lock or erase a replacement session. The four auth production files pass 146 focused cases in [mobile-auth-ownership.log](validation-logs/mobile-auth-ownership.log); they are also in the final full suite.
- Settings recovery/deletion/rotation handlers bind fresh proof to the original verified vault owner and server scope. Rotation's successful source result includes an exact completion scope, also checked when its alert's sign-out callback is pressed. Envelope upgrade holds a private original key and refuses a stale KDF continuation before processing-key shipment or cache mutation. Actual suspended owner/password-proof/KDF regressions pass in [mobile-settings-ownership.log](validation-logs/mobile-settings-ownership.log).
- Sign-out wipes the plaintext RAM fallback and locks immediately; it snapshots the old credential identity before network logout and retires cleanup when another login/origin takes ownership. Boot credential reads also cannot overwrite a newer login or resurrect a retired session. See [mobile-provider-boot-fence.log](validation-logs/mobile-provider-boot-fence.log).
- Health mirroring receives the original save ownership guard through permission/preference waits and checks it synchronously immediately before native save. The opt-in is reread after permission and preference revisions invalidate an in-flight older choice. Deferred account-replacement and opt-in-revocation tests verify no native call. Safety-plan Save ACK is serialized with draft writes and retains later edits. See [mobile-draft-progress-health-custody.log](validation-logs/mobile-draft-progress-health-custody.log), [mobile-safety-plan-late-ack.log](validation-logs/mobile-safety-plan-late-ack.log).
