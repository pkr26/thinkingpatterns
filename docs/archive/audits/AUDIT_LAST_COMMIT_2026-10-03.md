# Independent audit of the latest commit

Audited commit: `ad797b060ac5de986e2eac6a044da8d6439a1c03` (`fix: harden encrypted workflows and application reliability`). Parent: `9c1ba47508f474afc5f70588dd2771d80c2eece7`. Audit date: October 3, 2026.

The commit contains substantial working improvements, but its claim that stale ownership and asynchronous publication were fenced was incomplete. Independent reproductions found additional export, account-switch, draft, audio-custody and evidence-checking defects. This follow-up commit includes the fixes, regression tests and independent evidence. No deployment was performed.

## Scope and method

The review covered the changed backend, patient web, clinician portal, native mobile, migrations, operational scripts, CI/evidence tooling and remediation claims. Independent reviewers examined the application areas, followed by a separate review of the resulting fixes. New adversarial tests delayed specific reads, encryption, native writes and network boundaries instead of relying solely on the commit's existing tests.

The original source manifest was checked against the actual committed tree: all 1,133 listed files matched their recorded hashes and lengths; the sole intentionally excluded tracked file was the manifest itself. This authenticates the original commit's inventory, not these later working-tree changes. Original reports and their test logs remain historical evidence. Current verification is recorded below and in [the independent evidence directory](../../../reports/independent-commit-audit-2026-10-03/README.md).

The identifiers below are local to this follow-up audit. Each code finding was reproduced by a failing regression before its fix; the shell-wrapper finding also used the actual native preflight verifier. All nine final backend regressions additionally fail against an isolated copy of the unchanged original HEAD. Two reporting errors were checked directly against executable output and corrected separately. Tests and checks retained their existing coverage floors and release policies.

## Corrections to recorded claims

The current harness produces **89 BLOCKED, 4 FINDING, 13 INFO and 2 PARTIAL**, rather than the recorded 92/4/10/2. Its single-process guard refuses a two-worker configuration, so three downstream worker-attack probes are correctly reported as informational and unexercised. Counting those as blocked attacks overstated the evidence. All 11 campaigns and 108 verdict slots are present; completeness does not establish a clean security assessment.

Monitoring has **seven alert rules exercised by eight scenarios**, rather than eight alerts. The executable rules and test inventory establish that count. [REMEDIATION_STATUS.md](../../remediation-status.md) and the current red-team summary now distinguish the original checkpoint from this independent rerun; the original counts are retained as historical metadata.

## Remaining limits and release gates

The original commit correctly leaves real release blockers explicit. They remain unresolved: the patient web `security.txt` still needs the operator's real monitored contact/canonical URL; mobile registry audit still reports 28 high affected paths despite checked-in verified backports; full Xcode/signing and physical-device behavior are not independently established here. Hosted CI, production load, deployed TLS, delivered alerts and actual offsite/object-store recovery were not exercised.

The documented architectural verifier-replay, weak-password offline-guessing and server-visible metadata risks remain, as do two partial red-team boundaries. Human accessibility/usability/language review and prospective statistical/clinical validation cannot be inferred from automated tests. Full mutation campaigns were not rescored during this audit; their gate implementations and adversarial contracts were checked. No policy was weakened, operator contact invented, dependency finding allowlisted or clinical certification granted.

All database/browser checks used new synthetic local fixtures. No production deployment or customer-data mutation was performed. Owned loopback servers and the disposable PostgreSQL container/data volume have been removed; temporary database connection metadata, synthetic browser database and TLS keys were deleted.
