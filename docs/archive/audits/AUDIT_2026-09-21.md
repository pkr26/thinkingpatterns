# MindPattern — Deep Audit & Remediation Plan (2026-09-21)

Eight parallel deep audits covering: backend API, database/data layer,
security/crypto, pattern engine/statistics, mobile app (code/state/UI-UX),
therapist portal, DevOps/deployment, and testing/compliance.

**Overall score: 85/100**

Calibration note: this is an unusually disciplined codebase (deterministic
engine with real FDR control, zero-knowledge crypto pinned by cross-platform
vectors, 1,200+ behavioral tests, mutation gates, CI-proven encrypted
backups). Deductions concentrate in three places: the app cannot ship yet
(no native projects), two verified HIGH defects in the pattern engine, and
documentation drift in operator-facing files.

# PART 1 — FINDINGS (all, by area, severity-ordered)

## A. Backend API & application layer (90/100)

1. **Medium — Rekey mutates every entry blob without advancing `entries_revision`.**
   `backend/app/api/insights.py:441-551` rewrites all `Entry.blob`s in one
   transaction but never calls `_increment_entries_revision` (contract stated
   at `entries.py:343-344`). A client or portal mid-pagination across a rekey
   passes `expected_revision` checks and silently receives mixed old/new-key
   pages — undecryptable rows, no `collection_changed` signal.
   **Fix:** one `entries_revision` increment inside the rekey commit.

2. **Medium — Export insight pagination drops rows past the first 100-id chunk.**
   `backend/app/api/account.py:467-468`: `pending_ids = chunk_ids[processed_pos + 1:]`
   discards `pending_ids[EXPORT_METADATA_PAGE_SIZE:]`. Latent today (~93 rows
   max), live the moment retention or chunk size changes. Silent GDPR export
   truncation.
   **Fix:** `pending_ids = chunk_ids[processed_pos + 1:] + pending_ids[len(chunk_ids):]`
   plus a test with monkeypatched page size and >2 chunks.

3. **Medium — Measures reads contradict the documented pagination contract.**
   README.md:281 promises byte-bounded pages with continuation headers;
   `measures.py:236-268` and `therapist.py:673-735` have no byte bound
   (500 rows × 8192 b64 ≈ 4 MB wire), no `X-Next-Offset`, no revision marker;
   offset paging on a DESC list duplicates/skips under concurrent creates.
   **Fix:** port the entries page_bytes/revision pattern, or document the divergence.

4. **Low — README "complete" error-code list is stale.** README.md:295 omits
   `version_conflict` (`entries.py:421`) and `rekey_key_mismatch` (`insights.py:559`).
   **Fix:** add both; consider a CI grep to keep it complete.

5. **Low — Consent revoke/rewrap can 500 on concurrent therapist deletion.**
   `consents.py:467-501,529-565` take only the patient sharing lock; cascade
   delete between read and commit → `StaleDataError` → 500.
   **Fix:** take both locks (grant already does) or map to 404.

6. **Low — Export shares keyset rides a mutable column.** `account.py:261-289`
   keysets on `granted_at`, which re-grant rewrites; a re-grant mid-export
   drops that share. **Fix:** snapshot ids in the head transaction (L-8 pattern)
   or keyset on immutable `id`.

7. **Low — Comment drift on audit commits for empty pages** (`therapist.py:908-911`,
   `1142-1144`): comments claim empty pages are unaudited; the trailing commit
   audits them. Auditing empty reads is arguably correct — fix the comments.

8. **Low — Config gaps.** No upper bounds on `max_entries_per_user`,
   `max_user_blob_bytes`, `unlock_threshold_days`, `db_pool_timeout`
   (`config.py:330-357`); `analysis_blob_budget` floor (1024 B) is below one
   max-size entry and turns into an empty corpus that silently overwrites
   stored patterns (`insights.py:850-852`). Legacy `/api` mount sends no
   `Deprecation` header.

## B. Database & data layer (88/100)

1. **Medium — Export truncation bug** (same as A.2; confirmed at
   `account.py:468`; the `else` branch at line 470 is correct, proving the
   inconsistency).

2. **Medium — Schema-parity gate blind to type/default drift.**
   `alembic/env.py:70-76,91-95` calls `context.configure` without
   `compare_type=True` / `compare_server_default=True`, so the autogenerate
   parity test cannot detect the drift class already fixed once as L-33.
   **Fix:** set both flags; extend the parity test.

3. **Medium — Rekey holds one transaction across full-corpus crypto.**
   `insights.py:443-543`: up to 10k entries re-encrypted with per-row UPDATE
   round-trips in one open transaction — pins xmin (blocks vacuum), holds
   thousands of row locks; no `statement_timeout` /
   `idle_in_transaction_session_timeout` on the app pool (`db.py:106-113`).
   **Fix:** asyncpg `server_settings` timeouts + executemany batch updates.

4. **Medium-Low — Access audit trail is write-only.** No `SELECT` against
   `AccessLog` anywhere in `backend/app/`; neither patient nor therapist can
   read who accessed what; GDPR access requests require manual SQL;
   `ix_access_log_actor`/`ix_access_log_user` serve zero queries.
   **Fix:** consent-scoped audit read endpoint, or document SQL-only access
   in the DPIA/runbook.

5. **Low — Revoked consents permanently count against the grant cap**
   (`consents.py:328-340`): 100 historical grant/revoke cycles → can never
   share again. **Fix:** cap active-only, or add re-authenticated purge.

6. **Low — Redundant index** `ix_notes_therapist_patient` is a strict prefix
   of `ix_notes_therapist_patient_created` (`models.py:330-331`). Drop it.

7. **Low — Dead pairing codes have no steady-state sweeper** (pruned only
   inside mint, `therapist.py:431-433`). Move the prune into the daily sweep.

8. **Low — README misdescribes `MINDPATTERN_ANALYSIS_BLOB_BUDGET`**
   (README.md:444): it bounds corpus *load*, not stored blobs, and never
   raises 413. **Low — `users.is_active` is unreachable in production**
   (nothing sets it False outside tests): dead surface or missing admin
   feature — document which.

## C. Security & cryptography (88/100)

1. **Medium — Rotation success leaves the vault on the OLD data key.**
   `mobile/src/rotation.ts:197-225` rekeys the server corpus but never locks
   the vault or updates the biometric wrap; cleanup hangs off the success
   alert's OK button (`SettingsScreen.tsx:443-447`), which Android can dismiss
   without firing. In that window new entries are encrypted under the old
   (possibly compromised) key → permanently undecryptable; History renders
   them as tamper failures.
   **Fix:** inside `rotatePassword` on success, imperatively `vault.lock()`
   and `await disableBiometricUnlock(userId)` before showing the alert.

2. **Medium — Therapists have no credential or wrap-key lifecycle.**
   `PUT /account/credential` is `require_regular_user` (`account.py:574`);
   `wrap_pub_key`/`wrap_key_blob` are written only at registration. A
   forgotten therapist password permanently orphans every consent's wrapped
   key and all notes; a phished verifier is only fixable by account deletion.
   **Fix:** open credential rotation to therapist tokens; add a wrap-key
   rotation route; patients already receive `therapist_wrap_pub_key` in
   `ConsentOut`, so the existing rewrap flow can re-wrap without re-pairing.

3. **Medium-Low — Biometric unlock never verifies the unwrapped key**
   (`UnlockScreen.tsx:91-124`): a stale wrap "unlocks" with the wrong key and
   the whole journal reads as tamper failures. The password path runs
   `verifyUnlockProof`; the biometric path doesn't.
   **Fix:** verify after unwrap; on `"wrong"`, delete the wrap and show the
   password path.

4. **Low — secureStore device key uses the weaker Keychain class**
   (`secureStore.ts:60` `WHEN_UNLOCKED_THIS_DEVICE_ONLY` vs biometric's
   `WHEN_PASSCODE_SET_THIS_DEVICE_ONLY`). On a passcode-less device the bearer
   token is protected only by the OS sandbox.

5. **Low — Feedback blob replayable across recomputes.** AAD is just
   `("feedback", user_id)` (`insights.py:1180`); a malicious server can
   re-present an old valid blob. Bounded impact (question ranking only);
   add a date or state-seq part to the AAD.

6. **Low — Decoy salts keyed to `token_secret`** (`auth.py:134-140`): secret
   rotation changes every unknown-user salt, distinguishing existence for a
   longitudinal observer. Fix with a dedicated `MINDPATTERN_DECOY_SECRET` if
   rotation is ever exercised.

7. **Low — Pairing fingerprint check is passive.** Require an explicit
   "fingerprints match" confirmation tap in the grant dialog
   (`TherapistShareScreen.tsx:139-145`) so the MITM check is an action.

Documented residuals (immutable string copies in enclave/analyzer, base64
data key crossing `/processing/sessions`, pairing MITM without the human
fingerprint check, all-or-nothing epoch revocation) were reviewed and are
acceptable for v1 given TTL/single-use/purge mechanisms.

## D. Pattern engine & statistics (80/100)

1. **HIGH — Replication-gate bypass via evidence-date cap eviction.**
   `brain.py:3370-3372` stores only the newest `EVIDENCE_DATES_CAP=60`
   evidence days, but `_replication_satisfied` (`brain.py:3274-3277`) tests
   set membership against the truncated list. For any evidence-date kind with
   >60 evidence days, evicted days count as "new evidence" — a same-corpus,
   zero-new-data recompute satisfies "independent replication". **Verified
   empirically:** `mood_correlation:work` (73 evidence days) surfaced on a
   second identical-corpus run; with the cap lifted it correctly stayed a
   candidate. Defeats the flagship anti-fluke mechanism for the most-evidenced
   patterns.
   **Fix:** `any(_iso(d) > record.evidence_dates[-1] for d in signal.evidence_days)`
   (list is sorted), or persist a monotonic `evidence_days_seen` counter.
   Add a regression test with >60 evidence days.

2. **HIGH — Spanish topic mining runs with an English-only eligibility
   filter; README overclaims.** `eligible()` (`brain.py:3102-3111`) excludes
   `TOPIC_STOPWORDS` (English only); `LANGUAGE_FUNCTION_WORDS_ES` is used
   solely for detection. Verified: "para", "cuando", "porque", "ahora",
   "gente", "vida", "trabajo", "casa" all pass eligibility; a 130-day Spanish
   corpus produced a presence topic card for a filler noun ("terraza",
   share 0.577). Separately, `THEME_LEXICON` is English-only, so Spanish users
   get zero temporal/mood_correlation/link cards — contradicting
   README.md:117's "FULL analysis" claim.
   **Fix:** when `language == "es"`, union `LANGUAGE_FUNCTION_WORDS_ES` into
   eligibility exclusions; narrow the README claim; (Phase 2) build an ES
   theme set.

3. **Medium — Truncated entries fabricated as neutral mood 0.0.**
   `_parse_entries` replaces over-budget oldest entries with `text=""`
   (`insights.py:673-679`); the brain scores them 0.0, injecting fabricated
   neutral days into means/baselines/EWMA for prolific long-term users
   (>2M chars of window text).
   **Fix:** skip empty-text entries without an explicit mood tag from the
   mood series (keep them for cadence/calendar).

4. **Medium — Person anchoring not language-gated.** `_person_candidates`
   (`brain.py:2018-2066`) treats any recurring capitalized token as a name;
   German-style orthography capitalizes all nouns, so `language == "other"`
   mood-tagging users can get `source="person"` cards for common nouns.
   **Fix:** run person mining only for `language == "en"` (or an allowlist).

5. **Medium — Late-replicating statistical claims skip "emerging".**
   Promotion to `confirmed` compares `first_qualified` (`brain.py:3396-3398`),
   set at first *candidate* qualification: a pattern sitting as candidate
   ≥21 days jumps candidate→confirmed in one run; the first card the user
   sees carries the highest-confidence label.
   **Fix:** restart `first_qualified = today_iso` at the emerging transition.

6. **Low — Phrase pid anchor churns at window/budget edges** (`brain.py:2630-2669`):
   a chronic rumination's lifecycle restarts as a fresh candidate when the
   anchor sentence leaves the 180-day window.

7. **Low — Dead multi-word entries in the Spanish lexicon**
   (`sentiment_lexicon_es.py:629,645,689`: "eterno es", "por eso",
   "darme cuenta" can never match per-token; duplicates in
   `LANGUAGE_FUNCTION_WORDS_ES`).

8. **Low — Unbounded module-global `_FOLD_CACHE`** (`brain.py:1457`) grows
   for the process lifetime.

## E. Mobile app — code, state, UI/UX (78/100)

1. **CRITICAL — The app cannot build.** No `ios/`/`android/` projects
   (uncommitted by design); worse, `@notifee/react-native` and
   `react-native-health` are absent from `package.json:23-35`, so reminders
   and the HealthKit mirror are permanent "unavailable" seams that Settings
   still advertises (`nativeFeatures.ts:60-69`, `healthkit.ts:148-157`).
   All native hardening (FLAG_SECURE, allowBackup=false, usage strings,
   adjustResize) is pending.
   **Fix:** generate and commit native projects per `mobile/README.md`, add
   the two modules, wire `verify:native-release` into CI.

2. **High — Check-in vocabulary is English-only on the main screen.**
   `mood.ts:21-56` hardcodes MOOD/ENERGY/SLEEP labels and ACTIVITY_TAGS;
   `EntryScreen.tsx:626-769` renders them verbatim; the es catalog
   interpolates English words into Spanish a11y strings.
   **Fix:** display-label catalog keys keyed by option value; keep English
   tag *values* on the wire, render localized labels.

3. **High — Pre-threshold core loop is English-only.** `genericQuestions.ts:20-81`
   (the daily question for the entire 30-day baseline) and `promptChips.ts:13-34`
   are hardcoded English.
   **Fix:** `generic_questions_es.json` with parity test; catalog keys for chips.

4. **High — Haptics preference ignored until Settings is opened.**
   `haptics.ts` defaults `enabled=true`; `loadHapticsSetting()` is called only
   from `SettingsScreen.tsx:509`. The sensory-anxious cohort this setting
   exists for gets pulses on save/mood/feedback taps after every cold start.
   **Fix:** call `loadHapticsSetting()` in `SessionProvider` mount.

5. **Medium — Hardcoded `#b3261e` on the origin-change phishing warning**
   (`LoginScreen.tsx:231`): violates the no-hex-literals theme contract and
   measures 2.89:1 on the dark background — WCAG AA failure on a security
   warning. **Fix:** `t.colors.error` (6.8:1).

6. **Medium — Reminder notification copy hardcoded English**
   (`nativeFeatures.ts:108-112,159`). Route through `t()`.

7. **Medium — Touch targets below the app's own 44pt contract:** sleep
   options 40 (`EntryScreen.tsx:716`), prompt/tag chips ~33pt (527-540,
   750-769), theme radios/time chips 40 (`SettingsScreen.tsx:648,723`).
   **Fix:** `t.minTouch`/`hitSlop` uniformly.

8. **Medium — Spanish catalog mixes usted and tú registers** (~270 usted
   strings; tú forms at `es.ts:146-148,598+`). Normalize to usted.

9. **Medium — History renders up to 500 decrypted rows in a plain
   ScrollView** (`HistoryScreen.tsx:931`): no windowing, and holds all rows
   as plaintext in the JS heap — in tension with the decrypt-on-demand
   posture. **Fix:** FlatList with windowing.

10. **Low** — `muteNote` never auto-dismisses (`InsightsScreen.tsx:586,610`);
    README screens table omits Measures/TherapistShare screens; calendar
    VoiceOver reads raw ISO dates (`MoodCalendar.tsx:106-112`); `activeDays`
    can lag a day in an always-open app (`store.tsx:186-198`); onboarding
    restarts at panel 1 after backgrounding (`OnboardingScreen.tsx:48`).

## F. Therapist portal (84/100)

1. **High — Print output includes the entire interactive page, illegibly,
   with raw journal text.** The `@media print` block (`PatientView.tsx:1040-1046`)
   hides only two header rows; every card, including the evidence card with
   full decrypted journal text, prints light-on-dark (`#e7ecf5`) against
   forced white — near-invisible on paper, and emits text the print-only
   block deliberately excluded.
   **Fix:** add `no-print` to all interactive sections (or hide
   `main > *:not(.print-only)`).

2. **Medium — Multi-line text collapses.** `Note` (`ui.tsx:103-110`) is a
   plain `<p>`; notes, entries, and printed notes render without
   `white-space: pre-wrap` while `NOTE_TEMPLATES` encourage multi-line drafts.
   **Fix:** `pre-wrap` on note/entry render paths and the print block.

3. **Medium — Doc drift on the visit-anchor store.** Portal README still
   says localStorage and "a second browser sees the same anchor"; the design
   is per-tab sessionStorage (`platform.ts:96-122`) — two tabs now diverge
   silently. Fix docs/comments; state the per-tab contract.

4. **Medium — No credential lifecycle for therapists** (see C.2); no MFA
   option for an account class reading PHI-adjacent data; registration copy
   never warns that a forgotten password is unrecoverable.
   **Fix:** warning now; rotation + optional TOTP next.

5. **Medium — No retry affordance on load failures** (`PatientsView.tsx:53-56`,
   `PatientView.tsx:468-471`): static banner; recovery is reload or sign-out.

6. **Low** — Login form doesn't submit on Enter (`LoginView.tsx:219-279`);
   sensitive-caseload banner ignores fresher manual scan rows
   (`PatientsView.tsx:88` vs 240); note draft survives pattern↔general
   context switches (`PatientView.tsx:802-806`); `window.print()` and bare
   `crypto.getRandomValues` bypass the platform seam; patient list flashes
   "No patients" before first fetch, no search/sort; `decryptMeasure` clamps
   scores 0-100 instead of rejecting (`crypto.ts:263`); clinic-readiness gaps:
   no audit view (server collects `access_log` but exposes no read), no note
   edit history, no multi-therapist orgs/handoff/scheduling.

## G. DevOps, deployment & operations (88/100)

1. **High — Runbook host-gone restore commands are broken as written.**
   `docs/INCIDENT_RUNBOOK.md:135-140` sets `NEWEST=$(ls -1t /srv/restore/…)`
   (host path) then passes it into containers where the volume is `/restore`
   — verify and decrypt fail with file-not-found at the exact moment of
   disaster recovery.
   **Fix:** `basename` + `/restore/$NEWEST`; add the remote-fetch path to
   `rehearse_restore.sh` so the documented commands are machine-tested.

2. **High — `deploy/monitoring/verify.sh` runs in no CI job.** Zero workflow
   references; this repo already suffered this exact decay mode
   (mutation-mobile "had NEVER executed"). Alert/metric drift will be
   invisible. **Fix:** a 2-minute `ci.yml` job (PyYAML + promtool).

3. **Medium — No rollback story, and the entrypoint makes rollback unsafe by
   default** (`docker-entrypoint.sh:19` auto-upgrades on every boot; nothing
   documents rolling back after a migration lands).
   **Fix:** rollback section in `deploy/README.md` (restore point, downgrade
   policy or expand/contract migrations).

4. **Medium — Opt-in overlays drop the production hardening bar.**
   `deploy/backup-offsite/docker-compose.yml` and `deploy/monitoring/docker-compose.yml`
   have no `cap_drop`, `no-new-privileges`, or `read_only`, despite joining
   the production network — the backup-offsite container sits beside the
   database with S3 credentials loaded.
   **Fix:** the same hardening quartet; tmpfs for rclone `/config` and `/tmp`.

5. **Medium — `BACKUP_OFFSITE_MODE=fetch` + `restart: unless-stopped` =
   infinite re-fetch loop.** The overlay's own README invites `up -d`, which
   restarts the exited fetch container forever, hammering the remote.
   **Fix:** gate `restart:` on mode (`"no"` for fetch).

6. **Medium — No container image vulnerability scanning** (pip-audit/npm
   audit cover app deps only; nothing scans OS packages — Trivy/Grype).
   Backend image compiles asyncpg against live apt; backup image `apk add`s
   unpinned openssl/python3 — both rebuild non-reproducibly.
   **Fix:** Trivy scan in the `docker` CI job and release `image` job.

7. **Low** — rclone copies in-flight `.tmp` artifacts (add
   `--exclude 'mindpattern-*.tmp'`); no Docker log rotation (add
   `logging:` limits); "pin before production" for monitoring/offsite images
   is unenforced (add `verify.sh --production` digest assertion); no mobile
   release pipeline (no signing/EAS/fastlane/store path); alerts never page
   (no Alertmanager, no provisioned dashboards); release `verify` job gates
   coverage on Python 3.12 while the production image runs 3.14.
